# イカマチ (IkaMachi) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** スプラトゥーン3スケジュールを条件（モード×ルール×ステージ×時間帯）で監視し開始前にローカル通知するiOSアプリ＋ウィジェットを、テスト済みコアロジック付きで構築する。

**Architecture:** コアロジックはローカルSPMパッケージ `IkaMachiKit`（`swift test` でmacOS上テスト可能）。App/WidgetはSwiftUI+WidgetKitターゲットで、XcodeGen (`project.yml`) から生成。App Groupsでキャッシュ・条件を共有。

**Tech Stack:** Swift 6 / SwiftUI / WidgetKit / UserNotifications / BackgroundTasks / XcodeGen / GitHub Actions (macOS)

**環境制約:** ローカルMacはCLTのみ（Xcode本体なし）。iOSターゲットのビルド検証はCIで行う。ローカル検証は `swift test --package-path IkaMachiKit`。

**Files:**

- Test: `IkaMachiKit/Tests/IkaMachiKitTests/ModelTests.swift`

型定義（全てCodable/Hashable/Sendable）:

```swift
public enum GameMode: String, Codable, CaseIterable, Sendable, Hashable {
    case regular, bankaraChallenge, bankaraOpen, x, event, salmonRun
}
public enum GameRule: String, Codable, CaseIterable, Sendable, Hashable {
    case turfWar, area, tower, rainmaker, clam, salmonRun
    // splatoon3.ink rule文字列: TURF_WAR/AREA/LOFT/GOAL/CLAM
    public init?(inkRule: String) { ... }
}
public struct Stage: Codable, Hashable, Sendable, Identifiable {
    public let id: Int          // vsStageId（サーモンランstageは負のhash値で衝突回避: coopはID体系が別）
    public let name: String     // 表示名（日本語はcommonsマスタで解決、無ければAPI英語名）
}
public struct ScheduleSlot: Codable, Hashable, Sendable, Identifiable {
    public var id: String { "\(mode.rawValue)-\(startTime.timeIntervalSince1970)" }
    public let mode: GameMode; public let rule: GameRule
    public let stages: [Stage]; public let startTime: Date; public let endTime: Date
    public let eventName: String?   // イベントマッチ名（その他はnil）
}
public struct HourMinute: Codable, Hashable, Sendable, Comparable { public var hour: Int; public var minute: Int }
public struct TimeWindow: Codable, Hashable, Sendable {
    public var start: HourMinute; public var end: HourMinute  // start>end は日跨ぎ
    public var weekdays: Set<Int>  // 1=日…7=土（Calendar.weekday準拠）。空=毎日
}
public struct ConditionSet: Codable, Hashable, Sendable, Identifiable {
    public var id: UUID; public var name: String; public var isEnabled: Bool
    public var modes: Set<GameMode>; public var rules: Set<GameRule>
    public var stageIDs: Set<Int>; public var timeWindows: [TimeWindow]
    public var leadTimeMinutes: Int
}
```

- [ ] テスト: `GameRule(inkRule:)` 全5種マッピング、`ConditionSet` のJSON round-trip、`HourMinute` 比較
- [ ] 実装 → `swift test` PASS → Commit: `feat: core models`

**Files:**
- Create: `IkaMachiKit/Sources/IkaMachiKit/Engine/ConditionEngine.swift`
- Test: `IkaMachiKit/Tests/IkaMachiKitTests/ConditionEngineTests.swift`

```swift
public struct Match: Hashable, Sendable {
    public let slot: ScheduleSlot
    public let conditionSets: [ConditionSet]   // 1つ以上
}
public enum ConditionEngine {
    // calendar/timeZone注入でテスト決定論化
    public static func matches(slot: ScheduleSlot, condition: ConditionSet, calendar: Calendar) -> Bool
    public static func match(slots: [ScheduleSlot], conditions: [ConditionSet], calendar: Calendar) -> [Match]
}
```

セマンティクス: 空集合=制限なし。stageはどちらか片方含まれればtrue。timeWindowは「スロット時間と窓の重なり」(端点一致は重なりとみなさない)。日跨ぎ窓はその日の窓を翌日まで延長して判定。weekday指定は窓の開始側の曜日基準。isEnabled=falseは常に不一致。複数windowはOR。

- [ ] テストケース: 空条件で全マッチ / mode絞り / rule絞り / stage片方一致 / stage不一致 / 窓内・窓外・部分重なり / 日跨ぎ22:00-02:00で23:30スロットと01:00スロットがマッチ / 曜日指定 / isEnabled=false / 複数セットORで同一slotのMatchに両セットが入る / タイムゾーン依存（JST固定calendar）
- [ ] 実装 → PASS → Commit: `feat: condition engine`

### Task 4: NotificationPlanner（TDD）

**Files:**
- Create: `IkaMachiKit/Sources/IkaMachiKit/Engine/NotificationPlanner.swift`
- Test: `IkaMachiKit/Tests/IkaMachiKitTests/NotificationPlannerTests.swift`

```swift
public struct PlannedNotification: Hashable, Sendable, Identifiable {
    public let id: String       // "slot.id" 固定（条件が変わっても同一slotは同一ID）
    public let fireDate: Date; public let title: String; public let body: String
}
public enum NotificationPlanner {
    public static func plan(matches: [Match], now: Date, limit: Int = 50) -> [PlannedNotification]
}
public protocol NotificationScheduler: Sendable {
    func sync(_ planned: [PlannedNotification]) async
}
```

仕様: fireDate = startTime − max(leadTimeMinutes)（複数セット時は最大lead）。fireDate ≤ now は除外（ただしslot開始前なら now+5秒 に繰り上げ）。fireDate昇順でlimit件に打ち切り。title/bodyは日本語（ルール名・ステージ名・条件セット名を含む）。

- [ ] テストケース: lead計算 / 複数セットの最大lead採用 / 過去除外 / 開始直前の繰り上げ / limit打ち切り / ID決定論性
